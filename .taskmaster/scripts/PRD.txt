# Property Website Frontend - Product Requirements Document

## Project Overview

### Vision
Build a modern, high-performance, multilingual real estate platform frontend that enables users to seamlessly search, browse, save, compare, and book viewings for properties. The platform serves as the client-facing application that interfaces with a decoupled backend API.

### Project Goals
- Create an intuitive, fast, and responsive real estate search experience
- Support multiple languages (Bulgarian, English, Russian) with full localization
- Achieve excellent SEO performance and search engine visibility
- Provide real-time property data synchronization with backend API
- Enable property viewing bookings and user account management
- Deliver a scalable architecture ready for future enhancements

### Target Audience
- **Primary**: Property seekers (renters and buyers) in Bulgaria and surrounding regions
- **Secondary**: Real estate agents showcasing their listings
- **Tertiary**: Property owners looking to list their properties

## Technical Specifications

### Core Technology Stack
- **Framework**: Next.js 15.4 with App Router
- **Language**: TypeScript for type safety
- **Styling**: TailwindCSS + Shadcn UI components
- **Authentication**: Clerk or NextAuth.js
- **Data Fetching**: Server Components, SWR/React Query for client-side caching
- **Internationalization**: Built-in Next.js i18n with URL-based routing
- **Maps Integration**: Mapbox GL JS
- **Image Optimization**: Next.js Image component with WebP support from backend
- **Email Service**: Resend API for booking confirmations (backend integration)
- **Deployment**: Vercel with SSR, ISR, and edge caching

### Architecture Requirements
- **Monorepo Structure**: Shared types with backend via `@shared/types`
- **API Integration**: RESTful backend at `https://backend.yourdomain.com/api/*`
- **Rendering Strategy**: SSR for SEO, ISR for dynamic content, client-side for interactions
- **Performance**: Sub-3s page loads, 90+ Lighthouse scores
- **Accessibility**: WCAG 2.1 AA compliance
- **SEO**: OpenGraph, Schema.org markup, XML sitemaps

### Internationalization Requirements
- **Supported Languages**: Bulgarian (bg), English (en), Russian (ru)
- **URL Structure**: `/bg/`, `/en/`, `/ru/` prefixes
- **Content Localization**: All UI text, property descriptions, agent info
- **Auto-Detection**: Browser language with manual override
- **Translation Management**: JSON files in `locales/` directory

## User Experience Requirements

### Performance Standards
- **Page Load Times**: < 3 seconds on 3G networks
- **Core Web Vitals**: 
  - LCP < 2.5s
  - FID < 100ms
  - CLS < 0.1
- **Image Optimization**: 
  - Backend-delivered WebP format images
  - Next.js Image component for automatic optimization
  - Responsive images with proper sizing
  - Lazy loading for improved performance
  - Direct loading from backend domain for faster delivery
- **Bundle Size**: < 1MB initial JavaScript bundle

### Mobile Experience
- **Responsive Design**: Mobile-first approach
- **Touch Interactions**: Optimized for finger navigation
- **Search Functionality**: Simplified mobile search interface
- **Map Performance**: Optimized for mobile viewport and touch

### Accessibility
- **Screen Reader Support**: Semantic HTML and ARIA labels
- **Keyboard Navigation**: Full keyboard accessibility
- **Color Contrast**: WCAG AA compliance

## Data Integration Requirements

### API Endpoints
- **Properties**: CRUD operations, filtering, search
- **Agents**: Profile data, listings association
- **Bookings**: Visit scheduling, confirmation
- **Users**: Authentication, preferences, favorites
- **Categories**: Property types and features
- **Locations**: Cities, neighborhoods, coordinates

### Real-time Features
- **Live Updates**: Property availability status
- **Visit Scheduling**: Real-time calendar integration
- **Price Changes**: Immediate reflection of backend updates
- **New Listings**: Fresh content without page refresh

### Caching Strategy
- **ISR**: Property pages regenerated every 5 minutes
- **SWR**: Client-side caching for user interactions
- **CDN**: Static assets cached at edge locations
- **API Caching**: Appropriate cache headers for different data types
- **Image Caching**: Next.js automatic caching for backend-served WebP images

### Backend Image Integration
- **Image URL Structure**: Direct URLs to backend's local storage system
  ```
  ${NEXT_PUBLIC_BACKEND_URL}/images/listings/{listingId}/{filename}.webp
  ${NEXT_PUBLIC_BACKEND_URL}/images/agents/{agentId}/profile.webp
  ```
- **Image Loading Implementation**:
  ```tsx
  // Property images
  <Image
    src={`${process.env.NEXT_PUBLIC_BACKEND_URL}${listing.coverImage}`}
    alt={listing.title}
    width={1200}
    height={800}
    className="object-cover"
    loading="lazy"
    placeholder="blur"
    blurDataURL="data:image/jpeg;base64,..."
  />
  ```
- **WebP Format Support**: All images automatically served as WebP from backend
- **Responsive Images**: Multiple sizes generated by Next.js Image component
- **Error Handling**: Graceful fallbacks for missing or corrupted images
- **Progressive Loading**: Blur placeholders and smooth transitions
