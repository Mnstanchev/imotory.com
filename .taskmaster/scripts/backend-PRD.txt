# Property Website Backend API - Product Requirements Document

## Project Overview

### Vision
Build a robust, scalable backend API and admin panel that serves as the single source of truth for all real estate platform data. The backend provides secure, multilingual REST APIs and a comprehensive admin interface for managing properties, agents, bookings, and user interactions.

### Project Goals
- Create secure, performant REST APIs for all frontend functionality
- Build comprehensive admin panel for content management
- Implement multilingual content storage and retrieval (Bulgarian, English, Russian)
- Provide real-time data synchronization with frontend applications
- Enable scalable file upload and email notification systems
- Deliver role-based access control and security features

### Target Users
- **Primary**: Frontend applications consuming REST APIs
- **Secondary**: Platform administrators managing content via admin panel
- **Tertiary**: Real estate agents with limited admin access (Phase 2)

## Technical Specifications

### Core Technology Stack
- **Framework**: Next.js 15.4 with App Router (API Routes + Admin UI)
- **Language**: TypeScript for type safety
- **Database**: PostgreSQL via Neon.tech (serverless)
- **ORM**: Prisma with TypeScript integration
- **Authentication**: Clerk or NextAuth.js (admin roles)
- **Validation**: Zod schemas (shared with frontend via @shared/types)
- **File Storage**: Local file system with organized directory structure
- **Image Processing**: Sharp for automatic WebP conversion and optimization
- **Email Service**: Resend API for transactional emails
- **Deployment**: Vercel with serverless functions

### Architecture Requirements
- **Monorepo Structure**: Shared types and validation via `@shared/types` package
- **API Design**: RESTful endpoints with consistent response formats
- **Database Strategy**: Normalized schema with proper indexing for performance
- **Caching**: Response caching headers for frontend SWR integration
- **Security**: JWT-based authentication, input validation, rate limiting
- **Scalability**: Serverless functions with horizontal scaling capability

### Database Schema Design
- **Core Entities**: Listings, Agents, Users, Bookings, Alerts, Categories, Locations
- **Multilingual Support**: JSON fields for translatable content (en, bg, ru)
- **Relationships**: Proper foreign keys and indexed associations
- **Performance**: Strategic indexing on search and filter fields
- **Audit Trail**: Created/updated timestamps and user tracking

### Local Image Storage Architecture
- **Directory Structure**: Organized file system hierarchy
  ```
  /public/images/
  ├── listings/
  │   ├── {listingId}/
  │   │   ├── cover.webp
  │   │   ├── kitchen.webp
  │   │   ├── bedroom.webp
  │   │   └── bathroom.webp
  │   └── {anotherListingId}/
  └── agents/
      ├── {agentId}/
      │   └── profile.webp
  ```
- **Image Processing Pipeline**:
  1. Accept PNG/JPG uploads via multipart/form-data
  2. Validate file type, size, and security
  3. Convert to WebP format using Sharp library
  4. Apply compression (quality: 80-85)
  5. Generate unique filename with timestamp
  6. Save to organized directory structure
  7. Return public URL for database storage
- **URL Generation**: Public URLs accessible as `/images/listings/{listingId}/{filename}.webp`
- **Frontend Integration**: Direct image loading via Next.js Image component or standard img tags

### Image Upload API Implementation Example
**POST /api/upload/images**

**Request Format:**
```typescript
// Multipart form data
{
  file: File, // PNG or JPG file
  listingId: string, // Target listing ID
  category?: string // Optional: 'cover', 'gallery', 'floorplan'
}
```

**Processing Steps:**
1. Validate file type (PNG/JPG only) and size (max 5MB)
2. Sanitize filename and prevent path traversal
3. Create directory structure: `/public/images/listings/{listingId}/`
4. Convert image to WebP using Sharp with 80% quality
5. Generate unique filename with timestamp
6. Save processed image to target directory
7. Return public URL for database storage

**Response Format:**
```typescript
{
  success: true,
  data: {
    url: "/images/listings/{listingId}/{timestamp}.webp",
    filename: "{timestamp}.webp",
    size: 245000, // bytes
    dimensions: { width: 1200, height: 800 }
  }
}
```

**Implementation Example:**
```typescript
// /apps/backend/app/api/upload/images/route.ts
import { writeFile, mkdir } from "fs/promises";
import path from "path";
import sharp from "sharp";

export async function POST(req: Request) {
  try {
    const formData = await req.formData();
    const file = formData.get("file") as File;
    const listingId = formData.get("listingId") as string;

    // Validation
    if (!file || !listingId) {
      return Response.json({ error: "Missing file or listingId" }, { status: 400 });
    }

    const allowedTypes = ['image/png', 'image/jpeg'];
    if (!allowedTypes.includes(file.type)) {
      return Response.json({ error: "Only PNG and JPG files allowed" }, { status: 400 });
    }

    if (file.size > 5 * 1024 * 1024) { // 5MB limit
      return Response.json({ error: "File too large" }, { status: 400 });
    }

    // Process file
    const arrayBuffer = await file.arrayBuffer();
    const buffer = Buffer.from(arrayBuffer);

    // Create directory structure
    const uploadDir = path.join(process.cwd(), "public", "images", "listings", listingId);
    await mkdir(uploadDir, { recursive: true });

    // Generate filename and process image
    const timestamp = Date.now();
    const filename = `${timestamp}.webp`;
    const outputPath = path.join(uploadDir, filename);

    const processedImage = await sharp(buffer)
      .webp({ quality: 80 })
      .resize(1200, 800, { fit: 'inside', withoutEnlargement: true })
      .toFile(outputPath);

    // Generate public URL
    const publicUrl = `/images/listings/${listingId}/${filename}`;

    return Response.json({
      success: true,
      data: {
        url: publicUrl,
        filename: filename,
        size: processedImage.size,
        dimensions: { 
          width: processedImage.width, 
          height: processedImage.height 
        }
      }
    });

  } catch (error) {
    console.error('Upload error:', error);
    return Response.json({ error: "Upload failed" }, { status: 500 });
  }
}
```
