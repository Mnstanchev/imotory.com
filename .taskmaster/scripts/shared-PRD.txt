# Shared Types Package - Product Requirements Document

## Project Overview

### Vision
Create a centralized package containing all shared TypeScript types, Zod schemas, and validation logic used across the real estate platform's frontend and backend applications. This package ensures type safety, prevents API drift, and provides consistent validation across the entire monorepo.

### Project Goals
- Provide unified TypeScript types for all data models
- Create comprehensive Zod schemas for runtime validation
- Ensure type safety between frontend and backend APIs
- Enable consistent data validation across applications
- Support multilingual content type definitions
- Facilitate easy maintenance and updates of shared contracts

### Target Consumers
- **Frontend Application**: Type definitions for API responses and form validation
- **Backend Application**: Request/response validation and database model types
- **Development Tools**: Build-time type checking and IDE support

## Technical Specifications

### Core Technology Stack
- **Language**: TypeScript with strict type checking
- **Validation**: Zod for runtime schema validation
- **Build System**: TypeScript compiler with declaration files
- **Package Management**: Part of monorepo with proper workspace dependencies
- **Documentation**: TSDoc comments for all exported types

## Core Type Definitions

### 1. Listing Types
**Priority: High**

#### Base Listing Interface
```typescript
interface Listing {
  id: string;
  slug: string;
  title: MultilingualText;
  description: MultilingualText;
  price: number;
  currency: Currency;
  type: PropertyType;
  status: ListingStatus;
  specifications: PropertySpecs;
  features: PropertyFeature[];
  location: Location;
  images: LocalImage[];
  coverImage: string; // Primary image URL from local storage
  agent: Agent;
  createdAt: Date;
  updatedAt: Date;
  viewCount: number;
  isFeatured: boolean;
}

interface LocalImage {
  id: string;
  url: string; // Local storage URL: /images/listings/{listingId}/{filename}.webp
  filename: string; // Original filename with .webp extension
  category: ImageCategory; // 'cover', 'gallery', 'floorplan'
  alt: MultilingualText; // Alt text for accessibility
  dimensions: {
    width: number;
    height: number;
  };
  size: number; // File size in bytes
  uploadedAt: Date;
}

type ImageCategory = 'cover' | 'gallery' | 'floorplan' | 'exterior' | 'interior';
```

#### Supporting Types
- **PropertyType**: Enum for Houses, Apartments, Villas, Offices, etc.
- **ListingStatus**: Active, Pending, Sold, Rented, Inactive
- **PropertySpecs**: Bedrooms, bathrooms, size, year built, etc.
- **PropertyFeature**: Balcony, Garden, Parking, Pool, etc.
- **Currency**: BGN, EUR, USD with conversion rates

## Zod Schema Definitions

### 1. Validation Schemas
**Priority: High**

#### Listing Validation
```typescript
export const CreateListingSchema = z.object({
  title: MultilingualTextSchema,
  description: MultilingualTextSchema,
  price: z.number().min(0),
  currency: CurrencySchema,
  type: PropertyTypeSchema,
  specifications: PropertySpecsSchema,
  features: z.array(PropertyFeatureSchema),
  location: LocationSchema,
  agentId: z.string().uuid(),
  images: z.array(LocalImageSchema).min(1).max(20),
  coverImage: z.string().url(), // Primary image URL
});

export const UpdateListingSchema = CreateListingSchema.partial();

// Local Image Schema for backend storage
export const LocalImageSchema = z.object({
  id: z.string().uuid(),
  url: z.string().url(), // /images/listings/{listingId}/{filename}.webp
  filename: z.string().regex(/^.*\.webp$/), // Must be .webp extension
  category: z.enum(['cover', 'gallery', 'floorplan', 'exterior', 'interior']),
  alt: MultilingualTextSchema,
  dimensions: z.object({
    width: z.number().min(1),
    height: z.number().min(1),
  }),
  size: z.number().min(1), // File size in bytes
  uploadedAt: z.date(),
});

// Image Upload Schema for API endpoints
export const ImageUploadSchema = z.object({
  file: z.instanceof(File).refine(
    (file) => ['image/png', 'image/jpeg'].includes(file.type),
    { message: "Only PNG and JPG files are allowed" }
  ).refine(
    (file) => file.size <= 5 * 1024 * 1024, // 5MB limit
    { message: "File size must be less than 5MB" }
  ),
  listingId: z.string().uuid(),
  category: z.enum(['cover', 'gallery', 'floorplan', 'exterior', 'interior']).optional().default('gallery'),
  alt: MultilingualTextSchema.optional(),
});

// Image Upload Response Schema
export const ImageUploadResponseSchema = z.object({
  success: z.boolean(),
  data: z.object({
    url: z.string().url(),
    filename: z.string(),
    size: z.number(),
    dimensions: z.object({
      width: z.number(),
      height: z.number(),
    }),
  }),
  error: z.string().optional(),
});
```

### 2. Utility Functions
**Priority: Medium**

```typescript
export const getLocalizedText = (
  content: MultilingualText,
  language: Language,
  fallback: Language = 'en'
): string => {
  return content[language] || content[fallback] || content.en;
};

export const createSlug = (title: string): string => {
  return title
    .toLowerCase()
    .replace(/[^a-z0-9 -]/g, '')
    .replace(/\s+/g, '-')
    .replace(/-+/g, '-')
    .trim('-');
};

// Image utilities for local storage integration
export const getImageUrl = (
  baseUrl: string,
  entityType: 'listings' | 'agents',
  entityId: string,
  filename: string
): string => {
  return `${baseUrl}/images/${entityType}/${entityId}/${filename}`;
};

export const isWebPImage = (filename: string): boolean => {
  return filename.toLowerCase().endsWith('.webp');
};

export const generateImageFilename = (
  originalName?: string,
  category?: ImageCategory
): string => {
  const timestamp = Date.now();
  const categoryPrefix = category ? `${category}-` : '';
  return `${categoryPrefix}${timestamp}.webp`;
};

export const validateImageFile = (file: File): { isValid: boolean; error?: string } => {
  const allowedTypes = ['image/png', 'image/jpeg'];
  const maxSize = 5 * 1024 * 1024; // 5MB

  if (!allowedTypes.includes(file.type)) {
    return { isValid: false, error: 'Only PNG and JPG files are allowed' };
  }

  if (file.size > maxSize) {
    return { isValid: false, error: 'File size must be less than 5MB' };
  }

  return { isValid: true };
};
```

## Local Image Storage Integration

The shared types package provides complete type support for the monorepo's local image storage system:

### **Backend Integration**
- **Image Processing Types**: Complete schemas for Sharp-based WebP conversion
- **Upload Validation**: File type, size, and security validation schemas
- **Storage Types**: Directory structure and URL generation types

### **Frontend Integration**  
- **Image Loading Types**: Type-safe URL construction for Next.js Image component
- **WebP Support**: Complete type definitions for WebP image consumption
- **Error Handling**: Types for graceful fallbacks and progressive loading

### **Cross-Application Benefits**
- **Type Safety**: Prevents API drift between image upload (backend) and consumption (frontend)
- **Validation Consistency**: Same validation rules applied in both frontend and backend
- **Utility Functions**: Shared helper functions for image URL generation and validation
- **Constants**: Centralized configuration for file sizes, formats, and constraints

This ensures that image handling remains consistent, type-safe, and maintainable across the entire monorepo while supporting the local storage architecture.
